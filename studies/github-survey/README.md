# Survey of AI Research Methods on GitHub Compared with Ours

Full repo-by-repo screening is in **[catalogue.md](catalogue.md)** (72 screened repositories; 46 included), item-by-item scoring is in **[scorecard-results.md](scorecard-results.md)** (24 external repositories + our own pipeline scored on [`../how-to-measure/SCORECARD.md`](../how-to-measure/SCORECARD.md)), and ready-to-apply code and prompt specifications are in **[ai-instructions.md](ai-instructions.md)**.

## 1. What Other GitHub Research Repos Are Doing

We screened **72 public GitHub repositories** across six targeted `gh search` probes and inspected **40 repositories at the source-code, prompt, and GitHub-Issue level** ([`sources/a-apps-and-frameworks.md`](sources/a-apps-and-frameworks.md), [`sources/b-skills-and-written-methods.md`](sources/b-skills-and-written-methods.md), [`sources/c-scientific-and-benchmark-agents.md`](sources/c-scientific-and-benchmark-agents.md)). Public AI research projects divide into four distinct paradigms:

1. **Type A — Open-Source Deep Research Apps & Frameworks (14 inspected; 118,399+ combined stars):** Turnkey Python or TypeScript apps built around search/scraping APIs (Tavily, Firecrawl, Jina Reader, SerpAPI, SearXNG) across four sub-families ([`sources/a-apps-and-frameworks.md`](sources/a-apps-and-frameworks.md)):
   - **A1 — Recursive Breadth $\times$ Depth Tree Explorers** ([`dzhng/deep-research`](https://github.com/dzhng/deep-research) [19,885★], [`assafelovic/gpt-researcher`](https://github.com/assafelovic/gpt-researcher) [30,603★, Deep mode], [`AnotiaWang/deep-research-web-ui`](https://github.com/AnotiaWang/deep-research-web-ui) [2,226★], [`nickscamara/open-deep-research`](https://github.com/nickscamara/open-deep-research) [6,298★] — accessed 2026-11-09): Generate $B=4$ queries at depth $D=2$, extract atomic "learnings", halve breadth ($\lceil B/2 \rceil$) per depth level, and synthesize a report in one pass.
   - **A2 — Hierarchical Multi-Agent Graph Orchestrators** ([`langchain-ai/open_deep_research`](https://github.com/langchain-ai/open_deep_research) [12,677★], [`SkyworkAI/DeepResearchAgent`](https://github.com/SkyworkAI/DeepResearchAgent) [3,573★], [`SalesforceAIResearch/enterprise-deep-research`](https://github.com/SalesforceAIResearch/enterprise-deep-research) [1,224★], and `gpt-researcher` `multi_agents` — accessed 2026-11-09): A supervisor delegates sub-questions to isolated worker subgraphs, compresses findings (`compress_research`), and writes a master report.
   - **A3 — Iterative Search-Reflect-Refine Loops** ([`LearningCircuit/local-deep-research`](https://github.com/LearningCircuit/local-deep-research) [9,557★], [`langchain-ai/local-deep-researcher`](https://github.com/langchain-ai/local-deep-researcher) [9,409★], [`zilliztech/deep-searcher`](https://github.com/zilliztech/deep-searcher) [8,388★], [`jina-ai/node-DeepResearch`](https://github.com/jina-ai/node-DeepResearch) [5,241★], [`mshumer/OpenDeepResearcher`](https://github.com/mshumer/OpenDeepResearcher) [2,792★] — accessed 2026-11-09): Sequential or parallel search rounds driven by gap reflection, Milvus chunk routing, or token budgets (`TokenTracker` / `beastMode` in `jina-ai`).
   - **A4 — Interactive Canvas / Split-Step Web UIs** ([`u14app/deep-research`](https://github.com/u14app/deep-research) [4,687★], [`btahir/open-deep-research`](https://github.com/btahir/open-deep-research) [2,139★] — accessed 2026-11-09): Human-editable `<report-plan>` outlines or `@xyflow/react` node graphs in browser storage.
   - *Core Weakness:* **9 of 14** rely solely on prompt instructions for citations, and **10 of 14** are session-ephemeral. `dzhng` and `mshumer` store `learnings: string[]` detached from `visitedUrls: string[]`, breaking inline attribution.

2. **Type B — Skills, Prompt Packs, Written Methodologies & Persistent LLM Wikis (20 included; 15 inspected in full):** Our direct peers (`SKILL.md`, `CLAUDE.md`) across three sub-families ([`sources/b-skills-and-written-methods.md`](sources/b-skills-and-written-methods.md)):
   - **B1 — Hybrid Skill + Deterministic Python CLIs** ([`jordan-gibbs/hyperresearch`](https://github.com/jordan-gibbs/hyperresearch) [4,453★], [`199-biotechnologies/claude-deep-research-skill`](https://github.com/199-biotechnologies/claude-deep-research-skill) [1,212★], [`lingzhi227/agent-research-skills`](https://github.com/lingzhi227/agent-research-skills) [459★], [`fivetaku/insane-research`](https://github.com/fivetaku/insane-research) [292★], [`azagreev/DResearch-Skill`](https://github.com/azagreev/DResearch-Skill) [0★] — accessed 2026-11-09): Pair Markdown skills with zero-dependency Python CLIs enforcing SQLite FTS5 quote checks ($\ge 5$ words), numeric summary-to-body checks, MinHash source-independence clustering, Crossref/OpenAlex retraction checks, and JSONL ledger gates.
   - **B2 — Written Multi-Agent Epistemic Contracts** ([`Imbad0202/academic-research-skills`](https://github.com/Imbad0202/academic-research-skills) [56,172★] and forks [`xrb936`](https://github.com/xrb936/academic-research-skills-claude) / [`Clebeep`](https://github.com/Clebeep/academic-research-skills-claude-science-fixed), [`Weizhena/Deep-Research-skills`](https://github.com/Weizhena/Deep-Research-skills) [2,517★], [`AnkitClassicVision/Claude-Code-Deep-Research`](https://github.com/AnkitClassicVision/Claude-Code-Deep-Research) V4 [147★], [`oh-rid/deep-research`](https://github.com/oh-rid/deep-research) [40★], [`tonyazhuuki/deep-research-skill`](https://github.com/tonyazhuuki/deep-research-skill) [32★] — accessed 2026-11-09): Enforce **Paper-Blind Sprint Contracts**, **consequence-tiered subquestions** (`0.60`/`0.80`/`0.92`), **3-LLM CLI triangulation** (`Claude` + `Gemini agy` + `Codex`), and **Entity $\times$ Field JSON matrices** compiled deterministically via `generate_report.py`.
   - **B3 — Persistent LLM Research Wikis (`llm-wiki` Pattern)** ([`SamurAIGPT/llm-wiki-agent`](https://github.com/SamurAIGPT/llm-wiki-agent) [3,686★], [`PKU-DAIR/AutoSci`](https://github.com/PKU-DAIR/AutoSci) [1,729★], [`nvk/llm-wiki`](https://github.com/nvk/llm-wiki) [1,521★], [`MetamusicX/zissa-wiki`](https://github.com/MetamusicX/zissa-wiki) [62★], [`KevinYoung-Kw/robust-llm-wiki`](https://github.com/KevinYoung-Kw/robust-llm-wiki) [10★] — accessed 2026-11-09): Maintain 3-layer vaults (`raw/` $\to$ `wiki/` $\to$ `schema/`) via `ingest → query → lint`.

3. **Type C — Scientific, Literature & Discovery Agents (6 inspected in full):** Optimize for epistemic fidelity and perspective recall ([`sources/c-scientific-and-benchmark-agents.md`](sources/c-scientific-and-benchmark-agents.md)):
   - **[`stanford-oval/storm`](https://github.com/stanford-oval/storm) (31,846★):** Generates personas from related Wikipedia H2–H6 TOCs, runs expert Q&A with a **4-turn sliding answer mask** (2,500-word cap), or maintains a **Co-STORM mind-map (`KnowledgeBase`)** — accessed 2026-11-09.
   - **[`Future-House/paper-qa`](https://github.com/Future-House/paper-qa) (PaperQA2, 9,572★):** Concurrent **Ranking & Contextual Summarization (`RCS` 0–10)** over 10–30 hybrid chunks, injecting OpenAlex/Retraction Watch metadata and stripping internal secondary citations (`strip_citations`) — accessed 2026-11-09.
   - **[`stanford-oval/WikiChat`](https://github.com/stanford-oval/WikiChat) (1,626★):** 7-stage pipeline merging generation with **atomic parent-claim decomposition** (`generate_split_claims.prompt`) and Jaccard $> 0.8$ passage deduplication — accessed 2026-11-09.
   - **[`SakanaAI/AI-Scientist`](https://github.com/SakanaAI/AI-Scientist) (14,974★) & [`AI-Scientist-v2`](https://github.com/SakanaAI/AI-Scientist-v2) (7,486★):** Automate code experiments (4-stage Best-First Tree Search across 3 seeds in v2), `\cite` regex checks, and NeurIPS LLM + VLM figure-caption review — accessed 2026-11-09.

4. **Type D — Benchmark-Driven Long-Horizon Research Agents (6 included; 4 inspected in full):** ([`Alibaba-NLP/DeepResearch`](https://github.com/Alibaba-NLP/DeepResearch) [20,120★], [`MiroMindAI/MiroThinker`](https://github.com/MiroMindAI/MiroThinker) [8,449★], [`RUC-NLPIR/WebThinker`](https://github.com/RUC-NLPIR/WebThinker) [1,472★], [`TIGER-AI-Lab/OpenResearcher`](https://github.com/TIGER-AI-Lab/OpenResearcher) [1,269★] — accessed 2026-11-09) train 30B–235B models via SFT/RL for **100–600 tool calls** on `BrowseComp`, `GAIA`, and `HLE` ([`sources/c-scientific-and-benchmark-agents.md`](sources/c-scientific-and-benchmark-agents.md)). They pioneer context survival — recency-masked tool outputs (`keep_tool_result: 5`), Markovian round reconstruction (`Think`/`Report`/`Action`), goal-conditioned `visit(url, goal)` extraction, and line-numbered viewports (`browser.open(cursor, loc, num_lines)`) — but target short `\boxed{}` QA and score lowest (`3.3 / 8`) on long-form verification.

## 2. How They Compare to Our System (`~/dev/research/`) Step-by-Step

In **[scorecard-results.md](scorecard-results.md)**, our current Hybrid + R3 standard scores **8 / 8** on the Tier A Desk Scorecard (`D1–D8`), tied only with `SakanaAI/AI-Scientist` v1 (`8/8`) and ahead of `assafelovic/gpt-researcher` (`7/8`), `jordan-gibbs/hyperresearch` (`7/8`), `Imbad0202/academic-research-skills` (`7/8`), and `AnkitClassicVision/Claude-Code-Deep-Research` V4 (`7/8`). Type B repos are our closest structural peers (`6.3 / 8` mean vs `5.2 / 8` Type C, `4.9 / 8` Type A, and `3.3 / 8` Type D).

| Our Pipeline Step (`CLAUDE.md`) | Field Adoption (`/24`) | What We Do Better Than the Field | Where Specialized External Repos Beat Us |
|---|---|---|---|
| **1. Pre-Committed Proposal (`prior`, `disconfirmer`, `kill criterion`)** | **Rare (`3/24`, 12.5%)** pre-commit hypotheses/kill criteria; **20/24 (83.3%)** do sub-query planning (`D1=1`). | Every Tier-3 study pre-commits an expected answer, quantitative disconfirmer, rival hypotheses, riskiest-assumption probe, and kill criterion (`[repo: how-to-write-proposals-and-studies/PROPOSAL_TEMPLATE.md]`). | **`Imbad0202` Schema 13 (Paper-Blind Sprint Contracts)** requires the critic to lock 3–7 falsifiable `rejection_triggers` *before* seeing the draft. **`AnkitClassicVision` V4** tags subquestions `context` (`0.60`), `finding` (`0.80`), or `decision` (`0.92`) upfront. |
| **2. Prior-Work Search & Cross-Study Memory (`find_prior.py` + `INDEX.md`)** | **Uncommon (`7/24`, 29.2%)** persist reusable cross-run knowledge; **17/24** are stateless. | Mandatory `find_prior.py` search over 750+ studies (`INDEX.md`) + `reconcile_status.py` drift lint + project linking (`feeds:` / `docs/INTENT.md`) (`[repo: CLAUDE.md]`). | **`KevinYoung-Kw/robust-llm-wiki`** enforces a write-time `status: draft` vs `stable` gate so incomplete pages cannot be reused. **`MetamusicX/zissa-wiki`** uses a **3-step query cascade** (`index.md` $\to$ `wiki/syntheses/` $\to$ `related:`) keeping lookup context at 8–12 files. |
| **3. Tiered Search & Context Isolation (`maxTurns: 30`, Haiku `WebFetch`)** | **Very Common:** **23/24 (95.8%)** isolate raw scrapes (`D2=1`); **22/24 (91.7%)** cap turns/depth (`D3=1`). | Empirically A/B tested R3 search (`93.5%` quality at `53%` of naive tokens in `[repo: web-search-methodology/README.md]`), 3-tier fetch escalation, and 30-turn subagent caps. | **`Future-House/paper-qa`** scores every chunk `0–10` (`RCS`), strips secondary citations (`strip_citations`), and injects OpenAlex/Retraction Watch metadata. **`MiroThinker`** (`keep_tool_result: 5`) and **`Alibaba WebResearcher`** (Markovian `Think`/`Report`/`Action`) prevent intra-agent context rot. |
| **4. Separate Answer-First Writer (`README.md` $\le 3,500$ words + `ai-instructions.md`)** | **Common in A/B/C (`16/24`, 66.7%)**, missing in Type D (`\boxed{}` QA). | Explicit $\le 3,500$-word cap on `README.md`, answer-first structure in the user's wording, and operational blueprints in `ai-instructions.md` (`Won 2/2` pairwise package usefulness in `[repo: research-pipeline-hybrid-comparison/README.md]`). | **`jordan-gibbs/hyperresearch`** (Steps 14–16) and **`azagreev/DResearch-Skill`** (Phase 5) **tool-lock post-synthesis critique/patch agents to `[Read, Edit]` only** (forbidding `Write`), preventing the rewrite drift we observed in Arm B/C/D. **`Weizhena`** compiles JSON matrices deterministically via `generate_report.py`. |
| **5. Faithfulness Pass (`sources/` check + `[repo: ...]` re-verification)** | **Moderate (`14/24`, 58.3% pass `D4=1`)**; only **5/24** run deterministic quote/number scripts. | Fresh Opus faithfulness checker re-verifies numbers, quotes, and attributions against `sources/*.md` and re-fetches `[repo: <path>]` claims from primary URLs (`[repo: research-duplication-and-reuse/README.md]`). | **`hyperresearch`**, **`zissa-wiki`**, and **`AnkitClassicVision` V4** run **deterministic Python/SQLite FTS scripts** (`run verify`, `wiki.py quotes`, `citation_audit.py`) checking **100% of citation keys, $\ge 5$-word quotes, and summary numbers** in $<1$s for $0, gated by a `Stop` hook. |
| **6. Evidence Grading, Source Independence & Uncertainty (`(unverified)`)** | **Split by Type (`12/24`, 50.0% pass `D5=1`):** `7/7` Type B, `4/6` Type C, `1/7` Type A, `0/4` Type D. | Strict `[S]`, `(unverified)`, and `[repo: ...]` provenance markers plus mandatory `Confidence`, `Completeness`, `Known Gaps`, and `Self-check` sections (`[repo: CLAUDE.md]`). | **`hyperresearch`** and **`DResearch-Skill`** cluster syndicated wire reprints via **MinHash + canonical URL + dateline** (5 copies = **1 vote**). **`oh-rid/deep-research`** flags 3/3 LLM agreement without a URL as `[Consensus-only]`. **`tonyazhuuki`** separates **Design $\times$ Sample Size** from **Frontier Promise (`Resolving event`)**. |
| **7. Cost Tracking & Empirical Self-Benchmarking (`D7` & `D8`)** | **Extremely Rare (`3/24`, 12.5% pass `D8=1`):** Only `gpt-researcher`, `open_deep_research`, and `AI-Scientist` v1. | We commit 100+ full studies (`D7 = 1`) AND multi-arm controlled A/B evaluations with exact token, tool-call, wall-time, judge, and claim-entailment logs (`D8 = 1`). | **`langchain-ai/open_deep_research`** commits 100-task JSONL benchmark outputs with exact LangSmith token/USD links (`58M–207M` tokens). **`azagreev/DResearch-Skill`** maintains a 14-bug empirical `BUGLOG.md` pruning vacuous checks. |

## 4. How to Avoid the Issues Both We and Other Repos Are Dealing With

Across our own empirical studies (`[repo: research-pipeline-hybrid-comparison/README.md]`, `[repo: research-duplication-and-reuse/README.md]`) and **45+ real GitHub Issues inspected across external repositories**, eight failure modes recur across the field:

| Failure Mode | How It Manifested in Our System (`~/dev/research/`) | How It Manifested in External GitHub Issues | Exact Engineering Defense (Ours + Borrowed) |
|---|---|---|---|
| **1. Post-Draft Rewrite & Citation Drift** | Separate full-file `Write` passes in `Arm B` and `Arm C` dropped full claim entailment from **94% (Arm A)** to **74% (Arm B)** and **81% (Arm C)** (`400_at_80pct` $\to$ `"at least 400"`). | • `local-deep-researcher` [#90](https://github.com/langchain-ai/local-deep-researcher/issues/90) & [#92](https://github.com/langchain-ai/local-deep-researcher/issues/92): Overwriting `running_summary` wiped out earlier sections.<br>• `storm` [#573](https://github.com/stanford-oval/storm/issues/573): Regex `r"([.!?])\s*(\[\d+\])?\s*"` silently deleted `[2]` and later citations.<br>• `dzhng` / `mshumer`: Stored `learnings` without URLs. | 1. **Bind every note bullet to its URL + line span** in `sources/*.md`.<br>2. **Run `scripts/verify_study.py`** right after `README.md` is written.<br>3. **Tool-lock the faithfulness checker to `[Read, Edit]`** (`Patch, Never Regenerate` from `hyperresearch`). |
| **2. Evaluator Frame-Lock, Sycophancy & Silent Gate Bypass** | Blind holistic LLM judges gave `Arm B` **4–5/5 on groundedness** despite **26% drifted claims**, and swung **7 points** on reading order. | • `Imbad0202` (`showcase/README.md`): **21 of 68 refs (31%)** had errors surviving 3 LLM check rounds (7 marked `FIXED` at Stage 2.5).<br>• `AI-Scientist-v2` [#133](https://github.com/SakanaAI/AI-Scientist-v2/issues/133): Hardcoded whitelist silently skipped VLM review in **24 of 24 runs (`F11`)**.<br>• `open_deep_research` [#217](https://github.com/langchain-ai/open_deep_research/issues/217): `CORRECTNESS_PROMPT` omitted `{report}` placeholder. | 1. **Never rely on holistic LLM prose judges for factuality** — run `verify_study.py` + claim-by-claim URL spot-checks (`O3`).<br>2. **Paper-blind rejection triggers:** Checker reads proposal disconfirmers and `sources/*.md` tables *before* reading `README.md`.<br>3. **Fail-loud assertions** in all verification scripts. |
| **3. | **7. Scraper Anti-Bot Blocks, Silent Zero-Results & Schema Blindness** | Publisher 403/CAPTCHA pages or misquoted `gh search` operators (`"A OR B"` in one string returning `0` hits) stall naive searchers. | • `local-deep-research` [#8459](https://github.com/LearningCircuit/local-deep-research/issues/8459): Ingested HTTP 200 bot-challenge HTML into `research_library`.<br>• `local-deep-researcher` [#87](https://github.com/langchain-ai/local-deep-researcher/issues/87), `dzhng` [#126](https://github.com/dzhng/deep-research/issues/126), `btahir` [#30](https://github.com/btahir/open-deep-research/issues/30), `storm` [#547](https://github.com/stanford-oval/storm/issues/547): Silent 0-result searches caused ungrounded synthesis or crashes.<br>• `AI-Scientist-v2` [#126](https://github.com/SakanaAI/AI-Scientist-v2/issues/126): Plotting failed 5/5 rounds without `.npy` schema. | 1. **3-tier retrieval fallback** (`gh api` / `arXiv` / Unpaywall $\to$ headless Chrome $\to$ Bright Data).<br>2. **Verify extracted text length & content** (reject $<500$-char challenge pages).<br>3. **Inject explicit file/JSON schemas** into prompts when aggregating structured data (`AI-Scientist-v2` #126 fix). |

## Self-check

1. Why do Type B written-method and hybrid-skill repositories (`hyperresearch`, `Imbad0202`, `AnkitClassicVision` V4, `Weizhena`, `zissa-wiki`) score higher on our Tier A Desk Scorecard (`6.3 / 8` mean) than 10,000+ star Type A apps (`4.9 / 8`) and Type D benchmark agents (`3.3 / 8`)?
2. We already have a separate writer and an Opus faithfulness checker in `CLAUDE.md`. Why does borrowing `hyperresearch`'s **Patch, Never Regenerate (`[Read, Edit]`-only)** rule and `scripts/verify_study.py` solve a problem our current setup still has?
3. Suppose an external deep-research agent posts a 74% score on `BrowseComp` and an 8.1/10 score on a long-form report LLM judge. Based on the GitHub Issues uncovered in this survey, name three concrete ways that agent can still fail badly on our daily research tasks.

<details><summary>Answers</summary>

1. High-star Type A apps and Type D RL agents focus almost entirely on **retrieval breadth (`D1–D3`)** while omitting post-draft claim verification (`D4 = 0` in 9 of 14 Type A apps and 4 of 4 Type D agents) and abstention/uncertainty rules (`D5 = 0` in 6 of 7 scored Type A apps and 4 of 4 Type D agents). Type B repositories are built by practitioners running Claude Code / Codex on long-form synthesis who hit writer drift, ghost citations, and context rot directly, so 7 of 7 scored Type B repos enforce active verification (`D4 = 1`), explicit uncertainty/gap handling (`D5 = 1`), and persistent intermediate source notes (`D6 = 1`).
2. First, in `[repo: research-pipeline-hybrid-comparison/README.md]`, full-file `Write` passes introduced **19%–26% claim drift**, and regenerating a file to fix 3 errors can silently alter unaffected paragraphs or drop hedges. Restricting post-draft passes to `[Read, Edit]` (`Patch, Never Regenerate`) preserves verified prose byte-identically (`115/116` blocks in `Imbad0202`). Second, an LLM checker costs tokens and can still miss subtle URL/key mismatches (`21/68` refs survived 3 LLM rounds in `Imbad0202` v2.3), whereas a deterministic stdlib script (`scripts/verify_study.py`) checks 100% of citation links, verbatim quotes ($\ge 6$ words), summary numbers, and word counts in $<1$ second for $0 (`0%` $\to$ `100%` pass rate in `AnkitClassicVision` V4).
3. First, **short-answer RL lock-in and citation omission**: `MiroThinker` (74% BrowseComp) hardcodes `\boxed{}` short answers in its open-source prompt ([Issue #158](https://github.com/MiroMindAI/MiroThinker/issues/158)), and `WebThinker` (8.0–8.3 Glaive report judge) explicitly tells its planner *"No need to mention citations or references"* because the Glaive judge never checks URLs. Second, **search-time benchmark contamination and backend fragility**: `WebThinker` [#32](https://github.com/RUC-NLPIR/WebThinker/issues/32) and `Salesforce` [#4](https://github.com/SalesforceAIResearch/enterprise-deep-research/issues/4) committed plaintext benchmark answers on GitHub that live searchers retrieve directly ([`Alibaba` #251](https://github.com/Alibaba-NLP/DeepResearch/issues/251)), and switching Serper $\to$ Bing or changing the tool scaffold dropped `Tongyi-DeepResearch` by **>20 percentage points** ([`Alibaba` #218](https://github.com/Alibaba-NLP/DeepResearch/issues/218), [`OpenResearcher` #3](https://github.com/TIGER-AI-Lab/OpenResearcher/issues/3)). Third, **unverified synthesis drift across stages**: without lexicon anchoring and deterministic quote/citation checks, multi-stage agents suffer "ghost lexicon decay" ([`AI-Scientist-v2` #100](https://github.com/SakanaAI/AI-Scientist-v2/issues/100)) or silently skip verification gates ([`AI-Scientist-v2` #133](https://github.com/SakanaAI/AI-Scientist-v2/issues/133)).

</details>
