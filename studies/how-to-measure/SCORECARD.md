# Research Method Scorecard (`SCORECARD.md`)

This document is the operational instrument for comparing AI research methods — both across external GitHub repositories (`01-github-research-methods-survey`) and across internal pipeline experiments (`[repo: research-pipeline-hybrid-comparison/README.md]`).

Because our 5-repo empirical probe ([sources/b-tradeoffs-and-probe.md](sources/b-tradeoffs-and-probe.md)) found that **only 2 of 5 public repositories commit sample long-form reports**, **only 2 of 5 publish in-repo evaluation numbers (on incompatible benchmarks)**, and **only 1 of 5 publishes cost figures**, a single monolithic rubric fails on external repos. Accordingly, the scorecard is partitioned into **three measurement tiers**:

- **Tier A — Desk Scorecard (8 binary items, 0–8 points):** Scored strictly by inspecting repository files, prompts, and code (`gh api`). Requires **no execution and no published outputs**. Designed for $\ge 80\%$ inter-rater agreement between independent agents.
- **Tier B — Output Scorecard (6 items, gated):** Scored whenever a method publishes $\ge 1$ sample long-form report (in-repo or in an accompanying paper/dataset) or after a test run. Inherits the deterministic and judged report-quality gates from `[repo: research-quality-metrics/README.md]`.
- **Tier C — Run Scorecard (6 items, Pareto + consistency):** Scored only when executing methods head-to-head on shared questions ($N \ge 3$ questions, $k \ge 3$ runs per question).

---

## Core Scoring Principles (Gating, Not Averaging)

1. **Multiplicative critical gates ([AMSTAR 2, Shea et al. 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5833365/) — accessed 2026-11-09; `[repo: research-quality-metrics/README.md]`):** Never average desk features, output quality, and token cost into a single 1D leaderboard number ([AI Agents That Matter, Kapoor et al. 2024](https://arxiv.org/html/2407.01502v1) — accessed 2026-11-09). A method that fails a critical output gate (e.g., broken/fabricated links or $<80\%$ claim entailment) is capped at **Low** regardless of how polished its prose looks ([DeepResearch Bench II, Li et al. 2026](https://arxiv.org/html/2601.08536v3) — accessed 2026-11-09).
2. **Default execution path only:** For Tier A desk items, score **only** mechanisms wired into the repository's default workflow (`main.py`, runner script, or default `SKILL.md` / agent prompt). Do not award points for marketing claims in `README.md`, dead code, or unimplemented roadmap bullets.
3. **Binary criteria over partial credit ([ResearchRubrics, Sharma et al. 2025](https://arxiv.org/html/2511.07685v1) — accessed 2026-11-09):** In `ResearchRubrics`, binary (`0`/`1`) grading improved human–LLM judge agreement by **~20 percentage points** over ternary (`Pass`/`Partial`/`Fail`) grading (0.72–0.76 vs 0.53–0.57 Macro F1). All Tier A desk items use strict `0` or `1` binary rules.

## Tier A: Desk-Measurable Scorecard (Repo Inspection Only — 8 Binary Items)

**How to run a Desk Audit (~5 minutes, $0 API cost):**
1. Fetch the repository file tree (`gh api repos/<owner>/<repo>/git/trees/HEAD?recursive=1`) and `README.md`.
2. Read the core orchestrator/workflow file(s) (`src/`, `agents/`, `skills/`, or main Python/TS entry point) and any `eval` / `test` directories.
3. Score each of the 8 items below as **`1` (Yes)** or **`0` (No)** using the exact operational rule.

| ID | Metric Name | Definition | Operational Scoring Rule (`1` vs `0`) | Evidence Strength | Cost to Score | How It Can Be Gamed & Anti-Gaming Gate |
|---|---|---|---|---|---|---|
| **D1** | **Upfront Question Decomposition / Planning** | Method explicitly decomposes the user query into sub-questions, perspectives, or a structured outline *before* final report drafting. | **`1`:** Code or prompt explicitly generates sub-queries, perspectives, or an outline as a distinct step before synthesis ([STORM, Shao et al. 2024](https://arxiv.org/html/2402.14207v2) — accessed 2026-11-09; [Anthropic Multi-Agent Research System](https://www.anthropic.com/engineering/multi-agent-research-system) — accessed 2026-11-09).<br>**`0`:** Single-shot search or direct reactive loop without a planning/decomposition step. | **High** (STORM outline recall; Anthropic +90.2% multi-agent decomposition gain) | **Desk:** $0, ~1 min | *Gaming:* Prompt says "think step by step" without generating structured sub-queries/outlines.<br>*Gate:* Must produce an explicit list of sub-questions, search queries, or section outline consumed by the retrieval step. |
| **D2** | **Context / Subagent Isolation** | Raw scraped web pages or PDF chunks are processed, summarized, or filtered in isolated subagent contexts or a dedicated chunk-ranking/summarization step rather than dumped raw into a single monolithic writer context. | **`1`:** Spawns parallel/isolated subagents per sub-question OR runs an explicit chunk filter / contextual summarizer (e.g., BM25/embedding/Jev filter, PaperQA2 `RCS`, or Haiku `WebFetch` extraction) before the final writer ([GPT-Researcher Context Filter](https://github.com/assafelovic/gpt-researcher/blob/main/evals/context_filter/README.md) — accessed 2026-11-09; [PaperQA2, Skarlinski et al. 2024](https://arxiv.org/html/2409.13740v2) — accessed 2026-11-09; `[repo: web-search-methodology/README.md]`).<br>**`0`:** Appends raw full-page scrapes directly into one shared conversation history. | **High** (`[repo: web-search-methodology/README.md]`; PaperQA2 `RCS` ablation) | **Desk:** $0, ~1 min | *Gaming:* Defining multiple agent personas in one shared chat thread without separate context windows or chunk filtering.<br>*Gate:* Check whether raw page text is truncated/filtered/summarized in a separate LLM call or subagent before reaching the writer. |
| **D3** | **Explicit Search / Turn / Token Budget Cap** | Method enforces a bounded stop condition on search depth, breadth, tool calls, or token spend. | **`1`:** Code or agent config defines an explicit numeric cap on iterations, depth/breadth, `maxTurns`, or search calls (e.g., `depth=2, breadth=4`, `maxTurns: 30`, or max search rounds) ([Kapoor et al. 2024](https://arxiv.org/html/2407.01502v1) — accessed 2026-11-09; `[repo: CLAUDE.md]`).<br>**`0`:** Unbounded loop that runs until the LLM decides to stop. | **High** (`[repo: research-pipeline-hybrid-comparison/README.md]`: uncapped agents ran 31–52 calls vs 19–27 capped) | **Desk:** $0, ~1 min | *Gaming:* Setting an unrealistically high dummy cap (e.g., `max_steps=1000`).<br>*Gate:* Cap must be a practical operational bound ($\le 100$ tool calls or $\le 10$ recursive depth rounds per task) present in code/config. |
| **D4** | **Verification / Faithfulness Pass** | Method includes a distinct post-retrieval or post-draft verification step that checks claims/citations against source text, cross-references across $\ge 2$ domains, or runs an evaluator/critic pass. | **`1`:** Workflow includes a separate verification prompt/agent, NLI/hallucination checker, contradiction check, or mandatory multi-domain cross-check rule enforced in the researcher/writer prompt (`[repo: research-pipeline-hybrid-comparison/README.md]`; [ALCE, Gao et al. 2023](https://ar5iv.labs.arxiv.org/html/2305.14627) — accessed 2026-11-09).<br>**`0`:** Writer generates the final report in one pass from notes/context with no verification step or cross-reference requirement. | **High** (`[repo: web-search-methodology/README.md]`: +7.1% quality from verification step; `[repo: research-duplication-and-reuse/README.md]`: Opus checker caught copied `.724` error) | **Desk:** $0, ~2 min | *Gaming:* Prompt merely says "be accurate and cite sources" in the writer system prompt.<br>*Gate:* Must be either (a) a separate verification/eval pass in code/workflow or (b) an explicit rule requiring cross-checking claims across $\ge 2$ independent sources/domains or re-checking numbers/quotes against notes. |
| **D5** | **Abstention / Uncertainty / Gap Handling** | Method explicitly instructs the agent how to handle missing evidence, unanswerable sub-questions, or contradictions without guessing. | **`1`:** Prompts, code, or output template explicitly provide an abstention option (e.g., `"insufficient information"` in [PaperQA2](https://arxiv.org/html/2409.13740v2) — accessed 2026-11-09), an `(unverified)` marker, or a required `Limitations` / `Known Gaps` / `Contradictions` section (`[repo: research-quality-metrics/README.md]`).<br>**`0`:** Prompts force a definitive report with no instruction for unverified claims, missing data, or limitations ([BrowseComp, Wei et al. 2025](https://arxiv.org/html/2504.12516v1) — accessed 2026-11-09). | **High** (PaperQA2 21.9% abstention → 85.2% precision; BrowseComp 91% calibration error without abstention) | **Desk:** $0, ~1 min | *Gaming:* Boilerplate disclaimer at the bottom ("AI can make mistakes").<br>*Gate:* Must instruct the agent to flag specific unsupported/unverified claims inline or populate a task-specific gaps/contradictions section. |
| **D6** | **Audit Trail & Provenance Persistence** | Method saves intermediate research artifacts (search queries, scraped/fetched URLs, source notes, or trajectories) to disk/logs, not just the final prose report. | **`1`:** Code or workflow writes intermediate JSON/Markdown/log files containing queries, retrieved URLs/snippets, or researcher notes (`[repo: PRISMA 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC8005924/)` — accessed 2026-11-09; `[repo: CLAUDE.md]`).<br>**`0`:** Only outputs the final `report.md` or terminal string, discarding intermediate retrieval traces. | **Medium–High** (PRISMA 2020 item 7–8; required to run claim-vs-source verification) | **Desk:** $0, ~1 min | *Gaming:* Logging only timestamps or status messages without URLs/notes.<br>*Gate:* Saved files/logs must preserve at least the retrieved URLs and extracted notes/passages used to write the report. |
| **D7** | **Published Sample Outputs in Repo** | Repository commits at least one complete, readable sample output report generated by the method in version control. | **`1`:** At least 1 full generated report (`.md`, `.json` with full report text, `.html`, or `.pdf` of a generated report) is committed in the GitHub repository tree ([sources/b-tradeoffs-and-probe.md](sources/b-tradeoffs-and-probe.md)).<br>**`0`:** Zero full sample reports committed in the repo tree (empty `.gitkeep` folders, 3-line README summaries, or external-only links score `0`). | **High** (Probe finding: only 2/5 repos pass; required to run Tier B without executing code) | **Desk:** $0, ~1 min | *Gaming:* Committing a 1-paragraph toy snippet or an empty `.gitkeep` directory.<br>*Gate:* Must be a complete multi-paragraph research output ($\ge 500$ words) present in the repo tree. |
| **D8** | **Published Evaluation & Cost Transparency in Repo** | Repository commits reproducible evaluation scripts/results AND states per-run token or dollar cost figures. | **`1`:** Repo contains BOTH (a) quantitative benchmark/evaluation results or scripts (`evals/`, `evaluation/`, or benchmark table in `README.md`) AND (b) explicit per-run token count or dollar cost figures (`$X/report` or `Xk tokens/run`) in repo markdown/logs ([Kapoor et al. 2024](https://arxiv.org/html/2407.01502v1) — accessed 2026-11-09).<br>**`0`:** Missing either evaluation numbers or per-run cost/token figures in the repo (e.g., having a benchmark PNG without cost figures scores `0`). | **High** (Probe finding: only 1/5 repos passes both; prevents accuracy-without-cost leaderboard gaming) | **Desk:** $0, ~1 min | *Gaming:* Posting an unverified leaderboard bar chart image with no cost figures or eval scripts.<br>*Gate:* Must report both quality/accuracy numbers AND token/dollar cost in the repository. |

** Supplemental Desk Metadata (Record alongside D1–D8, not summed into the 0–8 score):**
- **Archetype:** `(a) Prompt/Skill workflow` | `(b) Single/Recursive agent script` | `(c) Multi-agent orchestrator` | `(d) Custom fine-tuned/RL model`
- **Adoption Friction:**
  - `Low`: Standard LLM API + 1 search API (or built-in CLI tools), runs via `pip`/`npm` or skill copy.
  - `Medium`: Requires multiple external paid APIs (e.g., LLM + Search + Scraper + Vector DB / Reranker) or Docker compose.
  - `High`: Requires custom GPU model weights (e.g., 30B local vLLM) + 4+ external APIs/sandboxes.

## Tier B: Output-Measurable Scorecard (When $\ge 1$ Sample Report Exists — 6 Metrics)

Apply Tier B whenever `D7 = 1` (sample output in repo), when an accompanying paper releases sample outputs, or on outputs generated during Tier C runs. Inherits the 3-layer gating structure from `[repo: research-quality-metrics/README.md]`.

| ID | Metric Name | Definition | Scoring Method & Target Threshold | Evidence Strength | Cost to Score | How It Can Be Gamed & Anti-Gaming Gate |
|---|---|---|---|---|---|---|
| **O1** | **Link Resolution Rate** *(Hard Gate)* | Percentage of cited URLs in the report that resolve (`HTTP 200`, non-404, non-fabricated domain). | **Deterministic script** (`HTTP HEAD/GET` on all markdown/footnote URLs).<br>**Target:** **100%** (any fabricated/broken URL caps report grade at *Low*). | **High** (`[repo: research-quality-metrics/README.md]`; `[repo: research-pipeline-hybrid-comparison/README.md]`: 100% across Arms A/B/C) | **Output:** $0 (0 tokens, ~10s HTTP check) | *Gaming:* Citing root homepage URLs (`https://en.wikipedia.org`) that always return 200.<br>*Gate:* Flag root-domain-only URLs; verify specific page support in **O3**. |
| **O2** | **Citation Density & Domain Diversity** *(Hard Gate)* | (a) Share of factual blocks/paragraphs with $\ge 1$ inline citation; (b) Unique cited URLs ($U$) and distinct registrable domains ($D$); (c) Decorative reference rate (references listed in bibliography but never cited in body). | **Deterministic regex + URL parser** (`[repo: research-pipeline-hybrid-comparison/README.md]`; [GPT-Researcher `evals/README.md`](https://github.com/assafelovic/gpt-researcher/blob/main/evals/README.md) — accessed 2026-11-09).<br>**Target:** $\ge 75\%$ cited factual blocks; $D \ge 8$ (Tier 2) or $D \ge 14$ (Tier 3); no single domain $>40\%$; decorative reference rate $\le 10\%$. | **High** (AMSTAR 2 critical search adequacy; GPT-Researcher `citation_faithfulness` & `diversity_ratio`) | **Output:** $0 (0 tokens, <1s script) | *Gaming:* "Citation theater" — appending 50 unread links or citing 3 mirrors of the same wiki ([ResearchRubrics](https://arxiv.org/html/2511.07685v1) — accessed 2026-11-09: 111 citations had lower accuracy than 31 citations).<br>*Gate:* Never reward raw URL count above the tier floor; penalize decorative (uncited) bibliography entries and check entailment in **O3**. |
| **O3** | **Claim-Level Source Entailment (Faithfulness)** *(Critical Gate)* | Fraction of sampled atomic factual claims in the report that are **fully supported**, **partly supported**, or **unsupported** by the specific web page cited for that claim. | **Sampled NLI / Agent Verification** ([ALCE, Gao et al. 2023](https://ar5iv.labs.arxiv.org/html/2305.14627) — accessed 2026-11-09; [DeepResearch Bench `FACT`, Du et al. 2025](https://arxiv.org/html/2506.11763v1) — accessed 2026-11-09; `[repo: research-pipeline-hybrid-comparison/README.md]`): Randomly sample 10 cited blocks (20–35 atomic claims), fetch the cited URLs, and grade each claim as `Fully Supported`, `Partly Supported` (scope-stretched or misquoted), or `Unsupported`.<br>**Target:** **$\ge 85\%$ Fully Supported**, **$\le 5\%$ Unsupported**. | **High** (ALCE human $\kappa = 0.698$; Mind2Web 2 attribution verifier 98.89% accurate; caught Arm B's 26% drift that blind LLM judges missed in `[repo: research-pipeline-hybrid-comparison/README.md]`) | **Output:** ~$0.05–$0.15 / report (10–25 page fetches + checker LLM pass) | *Gaming:* Post-rationalized citations ([Wallat et al. 2024](https://arxiv.org/html/2412.18004v1) — accessed 2026-11-09: up to 57% of citations) or stating only trivial truisms.<br>*Gate:* Audit exact numbers, quotes inside quotation marks, and causal attributions against the fetched source text; pair with **O4** (coverage) so trivial reports fail. |
| **O4** | **Checklist Coverage & Analytical Depth** *(Critical Gate)* | Fraction of mandatory task sub-questions, competing hypotheses, and analytical requirements satisfied by the report. | **Fine-grained Binary Rubric Checklist** ([DeepResearch Bench II, Li et al. 2026](https://arxiv.org/html/2601.08536v3) — accessed 2026-11-09; [ResearchRubrics, Sharma et al. 2025](https://arxiv.org/html/2511.07685v1) — accessed 2026-11-09; [Mind2Web 2, Gou et al. 2025](https://arxiv.org/html/2506.21506v1) — accessed 2026-11-09): Grade 15–30 task-specific binary (`0`/`1`) criteria with brief inline examples (do **not** use LLM-expanded rubrics, which degrade human alignment by 15–20%).<br>**Target:** **$\ge 75\%$ binary rubric pass rate** (commercial DRAs average 30–68%). | **High** (DRB II 91.75% ACC / 89.57% F1 vs humans; ResearchRubrics 0.72–0.76 Macro F1; Mind2Web 2 95.14% leaf agreement) | **Output:** ~$0.05–$0.25 / report (`DRB II` batch-50 costs $0.25/task) | *Gaming:* Verbosity padding — writing 7,500+ words to accidentally hit more rubric items ([ResearchRubrics](https://arxiv.org/html/2511.07685v1) — accessed 2026-11-09: length $r = 0.24\text{--}0.28$ with compliance).<br>*Gate:* Enforce **O6** word-count cap ($\le 3,500$ words) and include mandatory synthesis/counter-evidence items. |
| **O5** | **Gap, Contradiction & Uncertainty Honesty** | Whether the report explicitly flags unverified claims, source contradictions, and scope limitations rather than smoothing them over. | **Deterministic marker count + Anchored 1–5 Judge** (`[repo: research-quality-metrics/README.md]`; [PaperQA2 `ContraCrow`, Skarlinski et al. 2024](https://arxiv.org/html/2409.13740v2) — accessed 2026-11-09).<br>**Target:** Score $\ge 4/5$; zero smoothed-over contradictions. | **Medium–High** (AMSTAR 2 risk-of-bias discussion; PaperQA2 found 1.64 real contradictions/paper) | **Output:** ~$0.01 / report (bundled with judge pass) | *Gaming:* Listing generic boilerplate limitations ("more research is needed").<br>*Gate:* Rubric anchor for `4–5` requires naming *specific* missing numbers, conflicting studies, or `[unverified]` claims. |
| **O6** | **Readability, Actionability & Length Discipline** | Whether a human practitioner can quickly read the answer and act on it without wading through lab-report scaffolding or 7,000-word bloat. | **Word-count check + Length-Controlled Position-Swapped Pairwise Judge** ([Length-Controlled AlpacaEval, Dubois et al. 2024](https://arxiv.org/html/2404.04475v2) — accessed 2026-11-09; `[repo: research-pipeline-hybrid-comparison/README.md]`):<br>1. Check main report word count (target **1,500–3,500 words**; penalize $>4,000$ words unless split into modular files).<br>2. Run blind pairwise judge in **both reading orders** (Run 1: A vs B; Run 2: B vs A) on *Answer-First Readability* and *Decision Actionability*. | **High** (AlpacaEval-LC Spearman 0.98 with Chatbot Arena; Hybrid comparison showed 7-point position bias on single runs and penalized C's 7,739-word README) | **Output:** ~$0.04 / pair (2 swapped judge calls) | *Gaming:* Surface markdown polish — using bold tables and headers to score 89–92% on Presentation while failing Recall ([DeepResearch Bench II Table 3](https://arxiv.org/html/2601.08536v3) — accessed 2026-11-09).<br>*Gate:* Never use **O6** alone; **O6** only breaks ties among reports that pass **O1–O4**. |

## Tier C: Run-Measurable Scorecard (Head-to-Head Execution — 6 Method Metrics)

Apply Tier C when comparing candidate methods head-to-head on our own tasks. Requires running each method on **$N \ge 2$ questions** for **$k \ge 3$ trials per question** (when budget permits) to separate method differences from run-to-run noise.

| ID | Metric Name | Definition | How Computed | Evidence Strength | Cost to Score | How It Can Be Gamed & Anti-Gaming Gate |
|---|---|---|---|---|---|---|
| **R1** | **Total Token Spend & API Dollar Cost** | Total tokens (input + output + cache reads reported separately) and total USD cost (LLM + search/scraper APIs) per completed study. | Log from API usage headers / session transcripts (`scoring/cost_log.tsv` in `[repo: research-pipeline-hybrid-comparison/README.md]`). Plot against **O3/O4** as a 2D Pareto frontier ([Kapoor et al. 2024](https://arxiv.org/html/2407.01502v1) — accessed 2026-11-09). | **High** (Anthropic: tokens explain 80% of BrowseComp variance; multi-agent uses 15× chat tokens) | **Run:** $0 overhead (logged during run) | *Gaming:* Hiding subagent/pre-filter tokens (e.g., Haiku `WebFetch` or external reranker API calls) or reporting only uncached output tokens.<br>*Gate:* Log total wall-to-wall tokens across orchestrator, subagents, pre-filters, and verifiers, plus total USD. |
| **R2** | **Quality-Adjusted Cost Efficiency** | Verified checklist coverage and supported claims delivered per 100k tokens (or per $1.00 spent). | $\text{Efficiency} = \frac{\text{O3 (Supported \%)} \times \text{O4 (Checklist \%)}}{\text{Cost in USD (or 100k tokens)}}$ (`[repo: web-search-methodology/README.md]`). | **High** (`[repo: web-search-methodology/README.md]`: R3 achieved 1.9× higher quality/token than naive search) | **Run:** $0 overhead (derived from O3, O4, R1) | *Gaming:* Running on trivial Tier-1 questions where 1 search achieves 100% quality for 5k tokens ([GPT-Researcher `SimpleQA`](https://github.com/assafelovic/gpt-researcher/blob/main/evals/context_filter/README.md) — accessed 2026-11-09).<br>*Gate:* Compute only on matched Tier-3 multi-faceted questions. |
| **R3** | **Wall-Clock Latency** | Elapsed real time (minutes) from launching the research command to final verified report on disk. | `start_timestamp` to `end_timestamp` across parallel workers (`[repo: research-pipeline-hybrid-comparison/README.md]`; [Mind2Web 2 Table 3](https://arxiv.org/html/2506.21506v1) — accessed 2026-11-09). | **High** (Hybrid comparison: 14 min vs 5.5 min; Mind2Web 2: 5.7–13.7 min for DRAs vs 18.4 min human) | **Run:** $0 overhead | *Gaming:* Cranking concurrency past API rate limits, causing silent 429 drops on scraped pages ([Kapoor et al. 2024](https://arxiv.org/html/2407.01502v1) — accessed 2026-11-09).<br>*Gate:* Log failed/rate-limited tool calls alongside wall time. |
| **R4** | **Human Effort (Active Minutes)** | Total human minutes spent scoping/approving proposals or outlines before/during the run PLUS human minutes spent reviewing and fixing errors after the run. | Stopwatch log of (a) pre-run/in-loop intervention time and (b) post-run reading + fact-check correction time ([Millard et al. 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6911272) — accessed 2026-11-08 `[repo: research-duplication-and-reuse/README.md]`). | **Medium** (Direct operational cost to the repo owner; currently unmeasured in repo runs) | **Run:** Human timer log | *Gaming:* Claiming "0 human minutes (fully autonomous)" while producing a 7,500-word report with 26% drifted claims that takes a human 45 minutes to audit.<br>*Gate:* Always include post-run human verification/reading time in total human effort. |
| **R5** | **Multi-Run Consistency ($\text{pass}^k$ & Variance)** | Stability of checklist pass rate, claim faithfulness, and token cost across $k \ge 3$ independent runs on the same prompt. | Compute **$\text{pass}^3$** (fraction of mandatory checklist items passed in *all 3* runs, per [$\tau$-bench, Yao et al. 2024](https://arxiv.org/html/2406.12045v1) — accessed 2026-11-09), plus mean $\pm$ SD of tokens and **O3** claim support (`[repo: research-duplication-and-reuse/README.md]`). | **High** ($\tau$-bench: `gpt-4o` drops from 61% $\text{pass}^1$ to <25% $\text{pass}^8$; Q5 baseline tokens varied 855k–1,334k across identical runs) | **Run:** $3\times$ single-run execution cost | *Gaming:* Caching search/scrape results across the $k$ trials so retrieval variance is artificially zero.<br>*Gate:* Specify whether trials are full end-to-end runs (live retrieval variance + synthesis variance) or replay runs (synthesis variance only, as in [GPT-Researcher `replay.py`](https://github.com/assafelovic/gpt-researcher/blob/main/evals/context_filter/README.md) — accessed 2026-11-09). |
| **R6** | **Calibration Error (Brier / ECE)** | Alignment between stated confidence (`high`=0.90, `medium`=0.65, `low`=0.40, or 0–100%) and verified correctness over an accumulated claim ledger. | $\text{Brier} = \frac{1}{N}\sum_{i=1}^N (p_i - y_i)^2$ over audited claims ([BrowseComp Table 3](https://arxiv.org/html/2504.12516v1) — accessed 2026-11-09; `[repo: research-quality-metrics/README.md]`).<br>**Target:** **Brier $\le 0.15$**. | **High** (BrowseComp showed OpenAI Deep Research had 91% calibration error despite 51.5% accuracy) | **Run:** Tracked over 10+ studies in claim ledger | *Gaming:* Hedging every claim as `medium` (0.50–0.65) to avoid large squared errors.<br>*Gate:* Brier is a proper scoring rule; report alongside sharpness / resolution across confidence bins. |
