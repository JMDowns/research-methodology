# Q1 — Billing and caching facts for Claude Code on Max (accessed 2026-11-07)

## Short answers

1. **Plan-limit weighting: NOT published.** Anthropic's help pages describe Max limits only as a 5-hour session limit plus weekly limits, shared by claude.ai and Claude Code. They do not say how input, output, cache read or cache write tokens are weighted. The only quantitative evidence is community telemetry (GitHub issue #45756): the best fit is cache reads at about 0.1x input weight, but an earlier analysis fit 0x, and an Anthropic staffer did not confirm. Treat the riskiest assumption as **plausible but unverified**. What IS official: Claude Code docs say a one-line question in a long session "still draws usage for the whole conversation", and that cache misses and subagents are major causes of usage climbing. So context size does matter for plan usage; the exact weight is unknown.
2. **Long context pricing:** On API list prices, no premium for Opus 5.5 / Sonnet 5.5 (full 1M window at standard rate). Only Haiku 5.5 has a premium above 100k tokens (5x base input: $0.10 -> $0.50/MTok). Whether >200k counts more against Max limits: not documented. Docs say 1M-context use stays "covered by your subscription" on Max.
3. **TTL:** On a Claude subscription within plan usage, main conversation = 1 hour; subagents, compaction, forks, teammates, workflows = 5 minutes (default). Over plan limit (usage credits) or API key: 5 min for everything. Cache is per model; invalidated by model switch, fast mode toggle, MCP/tool-list change (when not deferred), deny of whole tool (when no tool search), compaction (conversation layer), image batch removal, Claude Code upgrade, idle past TTL. Effort change does NOT invalidate on Opus 5.5 / Sonnet 5.5 / Haiku 5.5.
4. **Subagents:** their requests "count toward the same usage limits as your main conversation". They do NOT share the parent's cache (different system prompt/tools), warm their own cache across their turns, and get only a 5-minute TTL by default. Forks DO read the parent's cache. Resumed subagents can read the cache their original run warmed (if within TTL).
5. **Images:** tokens = ceil(w/28) x ceil(h/28). Opus 5.5/Sonnet 5.5/Haiku 5.5 (4.7+ models) are the high-res tier: max long edge 2,576 px, max 4,784 tokens. 1920x1080 = 2,691 tokens; 1000x1000 = 1,296. Matches local measurement (2-7k tokens per screenshot). Claude Code drops oldest images in batches when request image limits are hit, which triggers a cache rebuild.
6. **Auto-compact:** native-1M models (Opus 4.7+, Sonnet 5+, Haiku 5.5, Fable) auto-compact at about 967K by default, so a 500-900k main thread is the default behavior. Configurable with `/autocompact 400k`, `autoCompactWindow`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `--autocompact`, per-subagent setting. `/compact` makes a separate request that re-sends the whole history plus a summary instruction: cheap-ish if cache is warm (reads prefix from cache), full uncached reprocess if cache expired. After compaction the next turn only rebuilds the short summary.

Boris Cherny (Claude Code team) pinned comment Apr 12: "Prompt cache misses when using 1M token context window are expensive"; suggested `CLAUDE_CODE_AUTO_COMPACT_WINDOW=400000`; attributed some cases to many skills/agents/background automations; did not confirm or deny cache-read weighting. Issue still open as of the fetch. Second domain for the claim: a WebSearch result summary (news.lavx.hu) repeated the same issue, but it is not independent.

### Q1.3 TTL and invalidation
- [Claude Code: How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching.md) — accessed 2026-11-07. TTL table: main conversation = one hour on a subscription within plan usage; five minutes on usage credits / API key / cloud. Everything else (subagents, workflows, teammates, forks, compaction, session titles) = five minutes, except server-controlled helper requests (one hour). Override with `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` (main) and `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (others), v2.1.242+; subagent frontmatter `experimental.cacheTtl` (v2.1.248+; 1h ignored while on usage credits). Invalidators: model switch (each model has own cache; includes opusplan toggles, skill frontmatter `model`, automatic fallback), fast mode toggle, tool definition set change (MCP connect/remove when tool search does not defer; plugin MCP), whole-tool deny without tool search, compaction, accumulated images (oldest batch removed), Claude Code upgrade, idle past TTL. Does not invalidate: CLAUDE.md edit mid-session (also not applied), permission mode, output style, skills, /recap, /rewind. Effort change keeps cache on Opus 5.5/Sonnet 5.5/Haiku 5.5. Cache scope: per machine and directory (system prompt embeds paths); parallel sessions in the same directory can share cache. Idle compaction exists on 1h TTL (`idleCompaction`, v2.1.290+).
- [API prompt caching docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) — accessed 2026-11-07 (first 100k of 164k chars). 5m default, 1h at 2x write; 5m write 1.25x; read 0.1x base, **0.05x for Opus 5.5 and Sonnet 5.5**; each read refreshes the TTL; min cacheable 512 tokens for 5.5 models. Confirms the two docs agree on TTL and price.

### Q1.4 subagents
- [Claude Code: Subagents](https://code.claude.com/docs/en/sub-agents) — accessed 2026-11-07 (first 100k of 117k chars). "It also sends its own requests, which count toward the same usage limits as your main conversation." Own fresh context window; forks inherit. Default max 20 concurrent. Background results arrive as a completion notification in a later turn. Model resolution order: per-invocation param, definition frontmatter, `CLAUDE_CODE_SUBAGENT_MODEL`, main model. Built-in Explore runs on the Opus alias on subscription.
- [Prompt caching page, "Subagents and the cache"](https://code.claude.com/docs/en/prompt-caching.md) — accessed 2026-11-07. "Its first request doesn't read the parent's cache, because the two prefixes differ" and subagents "get five minutes even on a subscription". Fork reads parent's cache.
- [Costs page](https://code.claude.com/docs/en/costs) — accessed 2026-11-07. "The subagent's own requests still draw on your usage." Agent teams about 7x tokens in plan mode.

### Q1.5 images
- [Vision docs](https://platform.claude.com/docs/en/build-with-claude/vision) — accessed 2026-11-07. Formula `ceil(w/28) x ceil(h/28)`. High-res tier (Claude 4.7 and later): 2,576 px long edge, 4,784 tokens max. Standard tier 1,568 px / 1,568 tokens. Table: 200x200 = 64; 1000x1000 = 1,296; 1920x1080 = 2,691; 3840x2160 = 4,784 (high-res). Max 8000x8000 px; stricter per-image limit above 20 images per request. Advice: downsample before sending if the extra fidelity is not needed. Pricing page lists 286 tokens as a per-image figure in some table (unclear context; not used).

### Q1.6 compaction
- [Model config, default auto-compact thresholds](https://code.claude.com/docs/en/model-config.md) — accessed 2026-11-07. "Models running with a native 1M window compact before the window fills, at about 967K tokens by default. These include the Fable models, Sonnet 5 and later, Haiku 5.5, and Opus 4.7 and later." Sonnet/Opus 4.6 without extended context compact at 200K. `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` makes 1M models compact at 200K. Ways to set the window: `/autocompact 500k`, `autoCompactWindow`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `--autocompact`, per-subagent setting.
- [Context window page](https://code.claude.com/docs/en/context-window.md) — accessed 2026-11-07. Compaction re-reads up to five recent files (files over 5k tokens come back as path only), re-injects skill bodies capped at 5k each / 25k total. Summarization request inherits thinking config (v2.1.198+).
- Prompt caching page (above): `/compact` cost described; warm cache = "a fraction of what the context size suggests"; cold cache = full uncached reprocess. Run at natural breaks, not mid-task.

## Local data cross-check (not from web)
- Local 4 "large cache rewrites" per main thread fit the doc'd causes (1h idle expiry, compaction). Subagents at 5-min TTL explain why subagent cache-writes may recur; local file shows cache write 57M vs read 2,019M in project A.
- opus-5-5 default context here is native 1M, so the owner's 467k-960k main threads are below the 967k default compaction point, i.e. the default allows them.

## Open questions
- The real plan-limit weight of cache read vs input vs output vs cache write is not published. Only community fits (0.1x, maybe 0x). Opus 5.5/Sonnet 5.5 API cache-read price is 0.05x, so the plan weight might also differ by model. Could be tested locally: compare `/usage` plan bars before/after a known cache-read-heavy workload (note the bars are coarse).
- Whether 1M-context turns count more against Max limits: undocumented (Boris Cherny's comment hints cache misses at 1M are the expensive part, not reads).
- Whether peak-hour weighting exists: only an unconfirmed community observation (25-35% in weekday 13-19 UTC).
- The "286 tokens" row in the pricing page and Opus 5.5's row in the model-config plan table were not examined.
- Subagent 5-min TTL default means long-running background agents that pause >5 min between turns rewrite their cache; settable via `subagentPromptCacheTtl=1h` (costs 2x writes, only within plan usage on subscription). Worth testing in Q3.
- GitHub issue was read through a summarizing fetch; open it directly if any quote is to be cited verbatim.
